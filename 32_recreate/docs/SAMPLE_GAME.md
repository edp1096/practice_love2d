# 완전한 샘플 게임 사양

## 이 문서가 바로잡는 것

`32_recreate`의 우선 결과물은 기능별 테스트 방의 집합이 아니다.
제작 엔진을 증명하는 가장 작은 단위는 제작자가 일반 입력만 사용해
처음부터 엔딩까지 플레이할 수 있는 한 편의 게임이다.

31 이전 프로젝트가 갖고 있던 메인 메뉴, 새 게임과 이어하기,
게임오버, 엔딩, 연결된 맵, 실제 NPC 애셋을 재작성 과정에서 누락하고
내부 feature 완성도만 높이는 것은 이 목표를 충족하지 않는다.

따라서 다음 두 결과를 구분한다.

- `sample game`: 아래 캠페인을 실제 플레이하는 완전한 한 편
- `engine fixture`: 충돌·패링·투사체 같은 규칙을 짧고 결정적으로
  검사하는 테스트 전용 장면

fixture가 아무리 많아도 sample game을 대신하지 않는다.

## 샘플 게임

작업명은 **고요한 숲의 수호자**다. 길게 만드는 대신 현재 엔진의
RPG와 액션 기능을 모두 실제 게임 흐름 안에서 한 번씩 사용한다.

### 플레이 흐름

1. 타이틀에서 `새 게임`, 저장이 있을 때 `이어하기`, `종료`를 고른다.
2. 마을에서 안내인에게 숲의 슬라임을 처리해 달라는 의뢰를 받는다.
3. 연습용 검을 받고 장착한다. 잡화점 실내의 상인에게 회복 물약을
   살 수 있고, 마을 집의 회복 구역에서 체력을 회복할 수 있다.
4. 두 실내를 직접 드나든 뒤 마을 출구를 통해 들판으로 이동하고
   최초 한 번만 얻는 월드 물약과 재진입 피해 구역을 확인한 뒤
   슬라임과 싸운다.
5. 숲 깊은 곳에서 수호자 보스를 쓰러뜨리면 퀘스트가 완료되고 보상을
   즉시 받는다.
6. 마을로 돌아와 안내인에게 완료를 보고한다.
7. 완료 대화를 선택하면 엔딩 화면이 열린다.
8. 플레이어가 쓰러지면 게임오버 화면에서 다시 시작하거나 저장을
   불러오거나 타이틀로 돌아간다.

일시 정지 메뉴에서는 계속하기, 저장, 타이틀로 돌아가기를 제공한다.
저장 뒤 게임을 종료하고 다시 실행해도 stage, 퀘스트, 아이템, 장비,
소지금과 언어가 복원되어야 한다.

## 표현과 애셋 원칙

루트 sample game은 31에서 검증된 다음 애셋을 실제로 사용한다.

- 플레이어 스프라이트
- 일반 슬라임과 보스 슬라임 스프라이트
- 안내인과 상인 NPC 스프라이트
- 월드 타일셋
- 한글 글꼴

`GUIDE`, `SHOP`이라고 적힌 `render.shape`는 새 profile이 외부 애셋
없이 즉시 부팅되도록 하는 제작용 placeholder다. 생성된 프로젝트에서
스프라이트를 등록하기 전까지는 의도된 fallback이지만, 완성 샘플의
안내인과 상인을 도형으로 남기지 않는다.

표현만 바꿀 때 대화·상점·퀘스트 파일을 수정하지 않는다. actor의
`render.shape`를 `render.sprite`로 교체하는 것으로 끝나야 한다.

## 재사용 가능한 엔진 경계

샘플을 완성하기 위해 게임 ID를 엔진 코드에 하드코딩하지 않는다.
다음 기능은 다른 프로젝트도 사용할 수 있는 `game flow` 계약으로
제공한다.

- title, playing, paused, gameover, ending 상태
- 새 session으로 시작하는 새 게임
- 지정 슬롯 이어하기와 저장
- 플레이어 사망 감지
- 데이터 action으로 게임 완료
- 이동·행동·상호작용을 막는 modal gate
- semantic snapshot과 debug protocol에서 현재 흐름 조회

캠페인 고유 stage, 대사, 퀘스트, 보스, 가격과 엔딩 문장은
`game/content`와 `game/game.lua`에만 둔다.

## 맵 연결

일반 플레이에서 debug 명령 없이 다음 경로를 왕복할 수 있어야 한다.

```text
                ┌── 작은 집(회복)
타이틀 ── 마을 ─┼── 잡화점(상점)
                └── 들판 ── 고요한 숲
                     ▲           │
                     └─ 귀환 ────┘
```

portal 목적지는 stage ID와 spawn point ID로 연결한다. 퀘스트 진행과
장비·재화는 stage를 이동해도 session에 남는다. 테스트 전용
`action_room`, `encounter_room`, `platformer_room`은 엔진 fixture로
유지하되 캠페인 동선에는 노출하지 않는다.

## 완료 판정

다음 항목을 모두 통과해야 이 샘플을 “완전하다”고 부른다.

- `love .` 실행 직후 타이틀 화면이 보인다.
- 키보드 또는 게임패드만으로 새 게임부터 엔딩까지 진행된다.
- 모든 캠페인 stage가 portal과 일반 상호작용으로 연결된다.
- 마을, 집과 잡화점은 실제 타일 레이어로 표시되고 충돌 도형이 타일을
  덮지 않는다.
- 안내인과 상인이 실제 스프라이트로 표시된다.
- 집의 회복 trigger가 진입 edge와 cooldown 계약대로 동작한다.
- 들판 월드 아이템은 저장되는 flag와 조건부 page로 중복 보상을 막고,
  피해 구역은 진입 edge마다 실제 체력과 사망 경계를 사용한다.
- 퀘스트 수락 전, 진행 중, 보스 처치 후 대사가 달라진다.
- 새 게임·들판·회복·퀘스트 수락과 완료가 데이터 기반 화면 알림으로
  전달되고, 대화나 상점과 겹치지 않는다.
- 마을·들판·숲은 서로 다른 배경 음악을 사용한다.
- 일반 적의 공격 예고에 맞춘 퍼펙트 패링이 적 경직, 전용 효과음과
  카메라 흔들림으로 보인다.
- 검의 공격력, 가죽 조끼의 방어력, 여행자 장화의 이동속도가 실제
  전투·이동과 HUD에 반영된다.
- 상점 거래가 실제 소지금과 inventory를 바꾼다.
- 플레이어 사망이 게임오버로, 최종 보고가 엔딩으로 이어진다.
- 저장 후 프로세스를 새로 띄워 이어하기가 실제 디스크 상태를
  복원한다.
- 자동화가 title, village, home, shop, quest, field, boss, return,
  ending, gameover와 save/load 화면을 각각 캡처하고 semantic 상태를
  함께 검증한다.
- `lovectl check`, Lua/Go/race/vet, deterministic package가 통과한다.

## 의도적으로 별도인 것

Windows와 macOS 실행 파일, 코드 서명과 installer는 Linux용 Maker 1.0
완료 뒤의 배포 작업이다. 엔진 fixture의 모든 실험 기능을 캠페인에
억지로 노출하는 것도 목표가 아니다. 샘플은 작게 유지하되 시작, 목표,
실패, 회복, 결말이 끊기지 않아야 한다.
